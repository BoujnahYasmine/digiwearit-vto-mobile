# Try-on architecture

Only the new screens are mounted. `/try-on` without a selected outfit returns to the entry screen; the legacy TryOnScreen and its duplicated camera/UI widgets were removed.

- `try_on_session.dart`: customer selection, confirmed photo, generated images and independent generation/payment states. Concurrent calls share one pending future; completed results are reused. Reset invalidates late callbacks and clears customer data. Partner authentication remains in ExperienceSession.
- `outfit_repository.dart`: Firestore outfits and look_categories, scoped filtering and record lookup. Category/model screens reuse real records. Existing injectable streams support tests.
- `outfit.dart` / `outfit_selection.dart`: preserve database fields and explicit reference images. Legacy records with a regional category but no style belong to Moroccan; explicit style fields take priority. Legacy broad styles retain garment-name grouping.
- `camera_service.dart`: camera discovery, initialization, minimum supported zoom, capture and gallery. The live screen owns lifecycle, countdown, permission UI and disposal.
- `try_on_request.dart`: confirmed photo, selected outfit, gender, style, category and optional color choice.
- `try_on_prompt.dart`: original strict garment/identity/pose prompt, including makeup, background and extra-prompt options. A golden fixture checks default prompt equivalence.
- `nano_banana_service.dart`: original Firebase AI model/configuration, image roles, Storage URI handling, HTTP loading, timeouts and returned-image validation. Reference-image fields take priority over display images. No UI screenshots are sent.
- `generation_screen.dart`: observes session; demo payment never restarts generation. Result requires completed generation and successful demo payment or authenticated partner coverage.
- Result/email/rating reuse generated bytes. Finish clears session, routes and image cache. Feedback sends only rating, optional comment, try-on ID, outfit ID and UTC timestamp.

Client reset discards late API responses; it cannot cancel a Gemini job already submitted remotely. Production idempotency, payment verification, feedback persistence and email delivery still require the backend. Tests inject generation/image loaders and do not spend on live Gemini requests.

Selection changes now invalidate generated media, payment, and pending callbacks while retaining upstream choices. Session disposal also discards late responses. Database normalization accepts female/male gender aliases, imageUrl display fallbacks, referenceImageUrl, and promptText; existing canonical fields retain priority. Category IDs remain in session/filtering, while human-readable category names are used in cards and generation metadata.
